# BloodLink – Security Operations & Clinical Governance Guide

## 1. Security Architecture Overview

BloodLink implements a zero-trust healthcare defense-in-depth security model:

```
[ Client Browser ]
      │  • Anon Key Only
      │  • Encrypted Session Storage
      ▼
[ Application Gateway (Flask REST API) ]
      │  • JWT Signature Verification (HS256)
      │  • Token-Bucket IP Rate Limiting
      │  • Granular Role Authorization Decorators (@require_admin)
      │  • Input Sanitization & Parameter Validation
      ▼
[ Database Engine (Supabase PostgreSQL 15+) ]
      │  • 100% Tables Protected by Row Level Security (RLS)
      │  • Security-Definer Functions (is_super_admin, has_admin_role)
      │  • Append-Only Forensic Audit Ledger (admin_action_logs)
      │  • Clinical Governance Modification Triggers
```

## 2. Incident Triage & Response Protocol

Security alerts generated by rate limiters, anomalous failed logins, or privilege violations trigger tracking in `public.security_incidents` (`INC-YYYY-XXXXX`):

| Incident Severity | Escalation Timeframe | Response Protocol |
|-------------------|----------------------|-------------------|
| **Critical** | Immediate (< 15 mins) | Automated IP throttling, active session revocation, Super Admin code-red notification. |
| **High** | < 1 Hour | Investigation by Security Auditor, account suspension pending challenge confirmation. |
| **Medium** | < 4 Hours | Telemetry inspection, audit log verification, configuration review. |
| **Low / Info** | < 24 Hours | Forensic log archiving and incident closure. |

## 3. Clinical Governance Modification Guard

Under no circumstances may platform administrators or developers casually modify biological compatibility matrices.

### Protection Mechanics:
1. `public.system_configuration` enforces database trigger `protect_clinical_rules_configuration()`.
2. Any attempt to update `config_key = 'clinical_transfusion_governance'` without a verified `medical_board_approval_token` inside the JSON payload is **aborted with an exception at the PostgreSQL database level**.
3. The Flask API layer similarly intercepts updates and returns HTTP 403 `CLINICAL_RULE_MODIFICATION_BLOCKED`.
4. All approved modifications require audited medical board tokens (e.g. `MBA-VERIFIED-2026-AABB`).
